# 공찾

이력서에서 직무·기술을 추출하고, 공개 채용 목록과 공고 원문을 조회하는 Next.js 앱입니다.

## 실행: Gemini 키 하나만 설정

Node.js 22.13 이상이 필요합니다. 루트 `.env` 파일은 준비되어 있습니다.

```dotenv
GEMINI_API_KEY=발급받은_키
```

```sh
npm install
npm run dev
```

http://127.0.0.1:3000 에 접속합니다. 키를 변경하면 서버를 재시작하세요. `.env.local`이나 운영체제 환경변수에 같은 이름이 있으면 `.env`보다 우선합니다. 키는 서버에서만 사용하며 `NEXT_PUBLIC_` 접두사를 붙이지 않습니다. Brave 등 다른 API 키는 필요하지 않습니다.

[Google AI Studio 키 발급](https://aistudio.google.com/apikey)에서 **Free tier 프로젝트**의 키를 사용하세요. 앱이 결제나 유료 티어 전환을 수행하지는 않습니다. 이미 결제가 연결된 프로젝트의 키는 앱에서 무료 키인지 판별할 수 없습니다.

## 무료 사용량 보호

- 기본 모델: `gemini-2.5-flash`, Google Search grounding 사용. 선택적으로 `GEMINI_MODEL=gemini-2.5-flash-lite`도 지원합니다. 지원하지 않는 모델로 자동 전환하지 않습니다.
- 검색 조건당 Gemini 요청 1회, 동일 요청 합치기, 결과 5분 재사용, 최소 15초 요청 간격, 서버 프로세스당 태평양 날짜 기준 하루 최대 20회 요청.
- 429 응답은 자동 재시도하지 않고 최소 60초 및 Retry-After만큼 쉬며 직접 채널 검색을 계속합니다. 실패 원문이나 API 키를 사용자에게 노출하지 않습니다.
- 위 제한은 앱의 보수적인 보호 설정이지 Google의 보장된 무료 할당량이 아닙니다. 실제 모델·프로젝트별 RPM/TPM/RPD는 [AI Studio](https://aistudio.google.com/usage?tab=rate-limit)에서 확인합니다.
- 제한 및 캐시는 메모리 기반입니다. 서버 재시작 시 초기화되고 여러 서버 간 공유되지 않습니다. 공개 다중 인스턴스 서비스에는 공유 저장소 기반 제한이 추가로 필요합니다.
- 직접 채널 검색 결과도 60초 재사용합니다. 조회 시각은 실제 수집 시각으로 유지하며, 재사용할 때도 마감/접수 전/등록 기간 조건을 다시 적용합니다.

공식 문서: [무료 요금과 검색 지원](https://ai.google.dev/gemini-api/docs/pricing), [한도 정책](https://ai.google.dev/gemini-api/docs/rate-limits), [검색 grounding](https://ai.google.dev/gemini-api/docs/google-search).

## 전체 공고 색인

검색할 때마다 사이트 첫 페이지만 보는 대신, 공개 채용 목록 전체를 미리 수집해 `data/job-index.json`에 색인하고 **색인 전체에서** 이력서와 맞는 공고를 찾습니다. 실시간 검색(각 사이트 최신 첫 페이지, Gemini)은 색인 이후 올라온 공고를 보완합니다.

```sh
npm run collect   # 처음 한 번 수동 수집 (약 10–15분)
```

- 서버는 색인이 6시간(`JOB_INDEX_TTL_HOURS`)보다 오래되면 검색 요청 시 백그라운드에서 다시 수집합니다. 수집 중에도 이전 색인으로 검색하고, 실패한 채널은 이전 수집 결과를 유지합니다. `JOB_INDEX_AUTO=0`이면 자동 수집을 끕니다.
- 수집 범위: 원티드 진행 중 공고 전체(공개 API 끝 페이지까지), 사람인 16개 직무 키워드별 최신 등록순 최대 30페이지×100건(`JOB_INDEX_SARAMIN_PAGES`), 기업 채용사이트 전체 목록. 목록에 없는 직무를 입력하면 그 키워드로 사람인 5페이지를 추가 수집해 색인에 넣습니다.
- 색인은 목록 정보(제목·회사·경력·지역·날짜·태그)만 저장합니다. 매칭 상위 20건은 검색 시 원문을 열어 본문을 채우고 결과를 색인에 기억합니다.
- 결과는 관련도 상위 최대 200건이며 화면에서 30건씩 더 볼 수 있습니다.
- 사이트에 부담을 주지 않도록 요청 간격을 둡니다(원티드 0.25초, 사람인 0.6초). 잡코리아는 robots.txt가 검색 페이지 수집을 금지해 색인에서 제외하고 실시간 첫 페이지만 조회합니다.
- 더 넓은 범위가 필요하면 공식 API 키 연동이 다음 단계입니다: 고용24(워크넷) 채용정보 API, 사람인 공식 API(oapi.saramin.co.kr).

## 검색 범위와 정확성

직접 조회: 원티드, 잡코리아, 사람인, 점핏과 아래 기업 채용사이트의 공개 채용 목록. 직무에 따라 원티드·점핏 조회는 생략될 수 있습니다.

- Greenhouse 공개 API: 당근, 센드버드, 몰로코, 쿠팡, 크래프톤 (한국 근무지만)
- 자체 채용 API: 토스(계열사 포함), 카카오(4개 직군 전체 페이지), 네이버, 우아한형제들
- 그리팅(GreetingHR) 채용사이트: 무신사, 컬리, 올리브영, 카카오페이, 카카오모빌리티, 현대오토에버, 11번가, 직방, 마이리얼트립, 와디즈, 뤼튼, 리벨리온, 팀스파르타, 스푼랩스. 목록은 페이지 데이터에서 읽고, 직무에 맞는 공고는 사이트당 최대 6건까지 상세 본문을 추가로 읽습니다.
- 네이버·우아한형제들은 목록에 본문이 없어 제목·직군만으로 매칭하며 근무지는 "원문 확인"으로 표시될 수 있습니다. 기업을 추가하려면 `src/lib/careers.ts`의 `GREETING_SITES` 또는 `providers.ts`의 Greenhouse 보드 목록에 넣습니다. 사이트 구조가 바뀌면 해당 채널만 "연결 실패"로 표시됩니다.

Gemini 확장 검색: 주요 채용사이트와 기업 채용사이트를 Google 검색으로 탐색합니다. 검색 출처에 실제 포함된 URL 및 해당 채용 검색 목록에서 발견한 같은 사이트의 공고 링크만 사용하며, 허용된 채용 도메인의 개별 원문에서 JobPosting 구조화 데이터 또는 사람인 상세 형식을 확인한 공고만 추가합니다. 모바일 잡코리아 개별 공고 주소는 데스크톱 원문 주소로 정규화합니다. 모델이 생성한 공고·날짜·URL을 그대로 표시하지 않습니다. 로그인·접근 제한·미지원 형식·마감 공고는 제외하며 검색 목록 자체를 공고로 표시하지 않습니다. 출처 상세에 검색 성공과 유효 공고 수를 구분해 표시합니다. 검색 호출에 성공해도 추가 공고가 0건일 수 있습니다.

**모든 채용사이트의 모든 공고, 검색 색인에 없는 최신 공고, 원문 자체의 정확성을 보장하지 않습니다.** 페이지 제한과 접근 제한이 있으므로 결과 0건은 해당 시장에 채용이 없다는 뜻이 아닙니다. 직접 목록은 원티드 최대 3페이지(120건), 잡코리아·점핏·사람인은 첫 검색 응답 범위입니다. 원티드·잡코리아·사람인의 상세 확인은 각각 최대 16건, Gemini 검색 출처는 최대 20개이며 출처가 검색 목록이면 목록당 최대 4개·전체 최대 12개의 상세 링크를 추가 확인합니다. 최종 결과는 최대 60건입니다.

- 신입: 신입 또는 신입 지원 가능/경력 무관이 명시된 공고. 경력 미확인 공고와 인턴·프리랜서 공고는 제외합니다.
- 인턴: 인턴이 명시된 공고만 표시합니다. 일반 신입 공고를 섞지 않습니다.
- 경력: 경력 또는 경력 무관/신입·경력 공고. 확인된 최소 연차가 지원자 경력보다 높으면 제외합니다.
- 최근 7·14·30일: **등록일이 확인된 공고만** 포함합니다. 수정일·수집 시각을 등록일로 대체하지 않습니다.
- 최신 등록순: 확인된 등록일 내림차순, 미확인 날짜는 뒤에 배치합니다.
- 날짜는 한국 시간 기준입니다. 날짜만 있는 마감은 그날 끝까지, 시각이 있는 마감은 해당 시각까지 접수로 계산합니다. 접수 시작 전 공고는 제외합니다.
- 원티드 API의 날짜만 있는 마감은 그대로 유지합니다. JSON-LD가 동일 날짜의 자정으로 표현하더라도 API의 날짜 정밀도를 우선합니다.
- 확인할 수 없는 시작일·등록일·마감일은 미확인으로 표시합니다. 월/일만 있는 목록의 마감에 임의의 연도를 붙이지 않습니다. 상세 원문과 채용 목록 확인 여부를 구분합니다.
- 지역 필터는 확인된 근무지 표기를 기준으로 적용합니다. 여러 모집 직무·근무 형태가 한 공고에 섞여 있으면 원문의 세부 모집 요강도 확인해야 합니다.

## 이력서 적합도

각 공고 카드에 이력서 적합도 점수(0–100), 제출 서류, 부족한 부분을 보여줍니다. 계산은 브라우저에서 이력서 전체 텍스트와 공고 내용을 비교해 수행하며, 이력서 텍스트는 서버로 보내지 않고 탭 메모리에만 둡니다(새로고침·파일 바꾸기 시 삭제).

- 점수 = 필수 기술(45) + 직무 일치(15) + 경력 연차(10) + 자격·어학·학력 요건(10) + 평균 스펙 대비(15) + 제출 서류 준비(5). 카드의 점수 배지를 누르면 항목별 점수와 감점 이유를 볼 수 있습니다.
- 평균 스펙: 회사명으로 기업 규모(주요 기업·공공기관·대학병원·일반 기업)를, 관심 직무로 직군을 추정해 프로젝트 수, 포트폴리오, 인턴 경험, 어학 점수, 학력, 관련 자격증, 대외활동 기준을 정하고 이력서에서 찾은 내용과 비교합니다(`src/lib/benchmark.ts`). 공찾이 정한 참고 기준이며 실제 합격자 통계가 아닙니다. 이력서 텍스트에서 찾지 못한 항목은 "확인 안 됨"으로 표시합니다.
- 필수/우대 구분: "우대사항" 이후 또는 "~우대"로 표시된 항목은 우대로 분류하고, 카드에서 점선 태그로 뒤에 표시합니다.
- 제출 서류는 공고 본문에 적힌 것만 표시합니다(이력서·자기소개서·포트폴리오·경력기술서·증명서류·사전 과제 등). 명시되지 않으면 "원문 확인"으로 표시하며 임의로 추정하지 않습니다.
- 자격 요건은 정보처리기사, 면허, 학위, 어학 등 정해진 목록만 인식합니다. 채용 목록만 확인한 공고는 본문이 짧아 부족한 부분이 적게 보일 수 있습니다.

결과 화면의 경력·등록 기간·정렬·지역 필터는 바로 검색하지 않습니다. 조건을 모두 고른 뒤 **재검색** 버튼을 눌러야 한 번에 검색하며, 채용 채널 선택은 검색 없이 현재 결과만 거릅니다.


```sh
npm run typecheck
npm test
npm run build
npm run verify:live
# .env에 키를 넣은 뒤 실제 Gemini 검색을 1회 호출해 확인
npm run verify:gemini
```

`verify:live`는 Gemini 사용량을 소모하지 않고 프론트엔드 신입·인턴, 백엔드 경력, 마케팅 인턴, 간호 신입을 검색합니다. 경력 조건, 마감, 접수 시작, 최근 7일, 최신순을 검사하고 원티드·잡코리아·사람인에서 결과 원문을 다시 읽어 날짜를 대조합니다. 실행 시점의 결과와 출처 상태는 `artifacts/verification-live.json`에 저장합니다. 결과 0건도 보고하며 그 조건의 실제 채용 존재를 증명하지는 않습니다.

`verify:gemini`는 .env를 로드해 인증, Google 검색, 원문 확인 경로를 실행하고 `artifacts/verification-gemini.json`에 기록합니다. 키가 없으면 실패하며, 키 값은 출력하지 않습니다. 자동 모의 응답 테스트의 통과가 실제 Gemini 인증 성공을 뜻하지는 않습니다.

## 문서와 개인정보

PDF·DOCX·TXT를 브라우저 안에서 읽습니다(파일당 5MB, 최대 2개). 원본/전체 텍스트는 서버나 Gemini로 보내지 않습니다. 직무·기술·경력·지역 키워드만 검색에 사용합니다. 무료 Gemini 입력은 Google 제품 개선에 사용될 수 있으므로 관심 직무에 이름·연락처를 입력하지 마세요. 북마크는 브라우저 localStorage에 저장합니다. 이미지 OCR, HWP, 자동 지원은 지원하지 않습니다.

Pretendard/Jua 글꼴은 SIL Open Font License를 따릅니다. 라이선스는 `public/fonts/`에 있습니다.
